### 改动要点

去掉不必要的串行等待，复用已有缓存，及时结束已经完成的流。主搜索默认 120 秒，补充来源默认 8 秒，两者同时开始；补充超时保留完成的答案和来源，搜索答案仍实时请求。

### 模拟测速

基线：pi-search `7a0be13`。使用同一份 `tests/search.bench.ts`，每项 1 次预热、10 次计量；Node.js `26.10.0`、Vitest `4.1.10`、TypeScript `6.0.3`。复用本机已安装依赖，未安装或升级依赖；Vitest 比锁文件记录的 `4.1.8` 更新，属于验证环境差异。

| 场景 | 模拟条件 | 改动前平均耗时 | 改动后平均耗时 | 耗时减少 |

这是本地模拟数据，不是实际模型 API 测速；不能推断每次真实搜索都会按表中比例加速。10 个样本不足以代表生产环境的 p95 或 p99，故不做相关延迟承诺。原始本机结果：`/tmp/pi-search-before.json`、`/tmp/pi-search-after.json`，临时文件不保证长期保留；可通过 `npm run bench -- --outputJson <path>` 重新生成。
